# Part 2 Project: Log File Analyser

## Brief

Build `logtools`, an installable Python package with a command-line tool that reads a web server's access log and reports what happened: how many requests succeeded and failed, when the site was busiest, which pages were most popular, and which requests were slowest.

```
$ logtools data/web_server.log --top 3
warning: skipped 5 malformed line(s): [101, 251, 401, 551, 701]
web_server.log: 800 requests

Requests by status
  200     713
  301      23
  404      46
  500      18
  error rate: 8.0%

Busiest hours
  18:00      79
  17:00      70
  19:00      62

Top paths
  /                      205
  /products              141
  /static/app.js          82

Slowest requests
    1.899s  GET  /api/search         07:06:22
    1.196s  GET  /api/search         11:17:56
    1.155s  POST /api/search         08:49:34
```

This project uses everything from Part 2: a package with modules and a `pyproject.toml` (Module 08), a dataclass with a property (09), generators, `key=` sorting and `Counter` (08, 10), a pytest suite (11), and an eye on efficiency, since logs can be huge (12).

## The data

`data/web_server.log` has 805 lines: 800 requests plus 5 deliberately malformed lines. It was generated by `data/make_web_log.py` with a fixed seed; rerun that script to recreate it. Each good line looks like:

```
203.0.113.7 - - [11/Nov/2026:09:15:02 +0000] "GET /products HTTP/1.1" 200 5123 0.042
```

Fields: client IP address, timestamp, request (method, path and protocol, in quotes), status code, response size in bytes, and the time taken to respond in seconds.

Run the tests from the repository root as you go:

```
python -m pytest part-2-intermediate-python/project/starter
```

## Requirements

1. `LogRecord` is a frozen dataclass with the seven fields of a log line and an `is_error` property.
2. `parse_line` turns one line into a `LogRecord`, raising `ValueError` for any malformed line.
3. `read_records` is a **generator** that yields records one at a time, skips malformed lines, and can report their line numbers.
4. `status_counts` and `error_rate` summarise status codes.
5. `busiest_hours` ranks hours of the day by number of requests.
6. `top_paths` ranks paths by number of requests.
7. `slowest_requests` returns the slowest requests.
8. `cli.build_parser` and `cli.main` provide the command-line tool, with `--top` and `--report` options, clear errors and exit codes.
9. `pyproject.toml` declares a `logtools` command that runs `logtools.cli:main`.

## Suggested order of work

1. Requirement 1, then 2: get `parse_line` working on the single example line in the tests, then on the malformed ones.
2. Requirement 3. Test it on the real file: you should get 800 records and 5 skipped lines.
3. Requirements 4 to 7, one function at a time. `collections.Counter` and `sorted(..., key=...)` do most of the work.
4. Requirement 8. Write `build_parser`, then `main`, running `python -m logtools.cli data/web_server.log` with `PYTHONPATH=part-2-intermediate-python/project/starter/src` set (or after step 5).
5. Requirement 9, then install your package in editable mode and try the real command:

   ```
   pip install -e part-2-intermediate-python/project/starter
   logtools data/web_server.log --report hours
   ```

   **Editable** (`-e`) means the installed command uses your source files directly, so changes take effect without reinstalling. Uninstall it afterwards with `pip uninstall logtools` if you also want to try the reference solution's command.

## Stretch goals

1. Add a `--since HH:MM` option that only counts requests at or after that time.
2. Add an `ips` report listing the client IPs with the most errors, a possible sign of a misbehaving client.
3. Make the tool read gzip-compressed logs (`access.log.gz`) as well, using the standard `gzip` module, without loading the whole file into memory.
