# CLAUDE.md

A self-paced Python course, from the basics to supervised and unsupervised machine learning. `README.md` is the source of truth: the curriculum, the **Build Instructions** (file layout, lesson format, Definition of done) and the **Build Progress** checklist. Read it before adding or changing course content.

## Environment

- Python 3.13 in `.venv` (`.venv/bin/python`). Dependencies are in `requirements.txt`: numpy, pandas 3, matplotlib, seaborn, scikit-learn 1.9, pytest.
- Run everything from the repository root.
- `pytest.ini` filters one warning that seaborn triggers inside Matplotlib (`vert: bool was deprecated`).
- If the editor reports "pytest could not be resolved", set the VS Code interpreter to `.venv`.

## Layout

```
part-N-name/
  MM-module-name/
    README.md                 overview, prerequisites, lesson links, 5-question quiz
    MM-LL-lesson-name/
      lesson.md               the lesson
      examples.py             every code block in the lesson, runnable
      ex_MM_LL.py             exercise stubs (raise NotImplementedError)
      sol_MM_LL.py            reference solutions
      test_ex_MM_LL.py        tests (at least 2 per exercise, one an edge case)
      figures/                PNGs written by examples.py (committed)
  project/
    README.md, starter/ (with the tests), solution/
data/                         generator scripts (make_*.py) and the files they write
```

Concept lessons have only `lesson.md` and `examples.py`, and end with 5 review questions with answers in `<details>`.

## Conventions

- Tests choose the module with `importlib.import_module("sol_MM_LL" if os.environ.get("COURSE_SOLUTIONS") else "ex_MM_LL")`. Project tests put `solution/` or `starter/` on `sys.path` the same way.
- `lesson.md` headings, in order: `# MM-LL Title`, What you will learn, Why it matters, Concepts, Common mistakes, Try it, Exercises (with the pytest command), Summary.
- Output shown in a lesson is pasted from actually running `examples.py`. Never write expected output by hand.
- Do not use a feature before the lesson that teaches it (for example generator expressions before 10-02, `groupby` before 14-05).
- `random_state=42` everywhere from Part 3 on.
- Plots: `matplotlib.use("Agg")` before importing pyplot; save to `figures/` with `dpi=100, bbox_inches="tight"`; tests close figures with an autouse fixture.
- Data path from a lesson: `Path(__file__).resolve().parents[3] / "data"`.
- `NotImplementedError` is a subclass of `RuntimeError`: a test using `pytest.raises(RuntimeError)` needs a `match=` so that stubs still fail.
- Library notes: pandas 3 uses `day_of_week`; in scikit-learn 1.9 use `CalibratedClassifierCV(SVC())` rather than `SVC(probability=True)`.

## Verifying a module

For each module, all of the following must hold:

```bash
# every example runs without warnings
for f in part-*/MM-*/*/examples.py; do .venv/bin/python -W error "$f" > /dev/null || echo "FAILED $f"; done
# every solution passes
COURSE_SOLUTIONS=1 .venv/bin/python -m pytest -q part-*/MM-*
# every stub fails (failures, not collection errors)
.venv/bin/python -m pytest -q part-*/MM-*
```

When a module passes, tick it in the README's Build Progress.
